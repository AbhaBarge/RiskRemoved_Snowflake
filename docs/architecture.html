As built:
  • Re-verification reruns each logged query from its stored text and bind, canonicalises the result (OBJECT_CONSTRUCT_KEEP_NULL rows sorted by their own JSON, SHA-256 of the JSON) and compares with the hash taken at gather time. Row and column order cannot change the hash. Time Travel is not used.
  • Reviewer checks (REVIEW_STR): numeric recompute (logged hash versus fresh hash, and every figure versus its source row); citation resolution; clause in effect for every deposit date; schema and unfilled placeholders; narrative trace (every rupee amount, date and count in the prose must equal a computed figure, and lakh/crore rounding is rejected).
  • Maker-checker: ATTEST_STR runs with caller's rights, requires the compliance role in session, requires the latest review to be APPROVE, and requires stored, recomputed and reviewed hashes to match. A refused attempt is logged REFUSED.
  • Hero demo: draft v1 carries a deliberately planted defect and is rejected with 2 defects; v2 passes all 5 checks. An AI narrative that self-approved but stated an unsupported total was rejected by the same reviewer.
  • Format: the artifact is JSON; an XML rendering of the STR is future scope.

Design Decisions (Gaps 1-9)

Gap 1: Transaction Grain Conversion Built

Decided: Each AMLworld pair row becomes two leg rows: one debit (negative amount), one credit (positive amount), sharing a txn_pair_id. Pair-level view for graph queries via self-join.
As built: RAW_TRANSACTIONS is leg-level with no label column; V_TRANSACTION_PAIRS is the pair-level view; labels live only in GROUND_TRUTH.TXN_LABELS.

Gap 2: SCD2 on DIM_PARTY Future scope

Future scope. DT_DIM_PARTY is current-state only. No effective_from/effective_to. SCD2 is a "What Production Would Need" slide item.

Gap 3: Sanctions Screening Future scope

Design: exact join against a consolidated sanctions table. The later markdown revised this to JAROWINKLER_SIMILARITY: an exact match raises a signal, the fuzzy band raises a review task, and a fuzzy match alone may never justify a filing.
Future scope: both versions. The matching thresholds are already in config and the landing table is in place; the loader, consolidated table and rule are the next increment.

Gap 4: Case Deduplication Built

Decided: "Existing" = CASE with status IN (OPEN, INVESTIGATING, DRAFTED) for same party_id. Different signal types merge into case_type = 'CROSS_DOMAIN'.
As built: signals are deduplicated first by signal_business_key with MERGE; cases are then grouped by party and open status as designed. The cross-domain re-typing needs two distinct rules, so it comes into play as rules are added.

Gap 5: Evidence Pointer Resolution Built, changed

Decided: Separate query log table. EVIDENCE stays clean (ref_type, ref_id, as_of_ts). EVIDENCE_QUERY_LOG stores sql_text and result_hash, linked via FK.
As built: the reviewer does not re-run SQL with AT(TIMESTAMP => as_of_ts). Time Travel binds per table reference, retention is short, and dynamic tables are not freely time-travellable, so correctness would have depended on it. Instead the log stores a canonical result snapshot and a versioned hash (SQL-1), and the reviewer reruns the stored SQL and compares hashes.

Gap 6: STR Generation Changed

Design: generate_str_xml() assembles XML with xml.etree, validated against a schema; the LLM never touches XML.
As built: FIU-IND publishes a form, not an XML schema. DRAFT_STR fills a governed template (FIU_IND_STR v1, an internal transcription) and stores the artifact as JSON with a SHA-256 hash; a PDF is rendered in the agent database. XML rendering is future scope, and no conformance with FIU-IND's filing gateway is claimed.

Gap 7: Verified Query Inventory Future scope

Future scope: 20 verified queries across 8 categories. GROUND_TRUTH.GOLDEN_QUESTIONS is in place for them; Cortex Analyst is already wired to the semantic view and used by the Ask page and Slack bot.

Gap 8: RLS Roles Roles only

Design: two roles, branch analyst (Mumbai) and compliance officer, with row access on DT_TRANSACTIONS_ENRICHED and DT_DIM_PARTY and masking on PAN/Aadhaar.
As built: BRANCH_ANALYST_MUMBAI_DEV, BRANCH_ANALYST_DELHI_DEV, COMPLIANCE_OFFICER_DEV and hosted-app roles exist. Attaching row access and masking policies is future scope. CASE_RECORD.branch_region is denormalised so a policy could filter cases later. The compliance role's one enforced power is ATTEST_STR.

Gap 9: Replay Harness Built, extended

Decided: Python script using the Snowflake connector, INSERT INTO batches, time.sleep(), and an --inject flag. No Snowpipe Streaming SDK.
As built: as decided, plus the in-Snowflake simulator (SIM_CONTROL). See diagram 18.
